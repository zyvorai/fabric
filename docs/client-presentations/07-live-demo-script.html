Demo 1: Create a VM from Cloud Image

Duration: 5 minutes

"Let me show you how fast it is to go from nothing to a running VM. We will create a VM from an official Ubuntu cloud image with a single command."

Step 1: List available images

zyvorctl image list

Show the built-in cloud image catalog.

Step 2: Create the VM

zyvorctl create demo-web \
  --image=ubuntu-24.04.qcow2 \
  --cpus=2 \
  --memory=2048

Point out: one command, no XML, no complex configuration files.

Step 3: Start the VM

zyvorctl start demo-web

Step 4: Verify it is running

zyvorctl list

Show the VM status: name, state, CPU, memory.

"That is it -- four commands to go from zero to a running Ubuntu VM. No YAML manifests, no XML domain definitions, no multi-page wizards."

Demo 2: Advanced VM Configuration

Duration: 5 minutes

"Now let me show you some of the advanced options. Zyvor Fabric supports cloud-init, GPU passthrough, TPM, and more -- all from the CLI or API."

Step 1: Create a VM with cloud-init

zyvorctl create demo-app \
  --image=ubuntu-24.04.qcow2 \
  --cpus=4 \
  --memory=4096 \
  --cloud-init-hostname=app-server \
  --cloud-init-packages=nginx,htop

Explain: cloud-init runs on first boot and configures the VM automatically.

Step 2: Show VM details

zyvorctl info demo-app

Show the full configuration: CPU, memory, disk, cloud-init settings.

Step 3: Show JSON output

zyvorctl list -o json

Demonstrate the scriptable JSON output for automation.

Step 4: Show the API directly

# Authenticate and get JWT token
TOKEN=$(curl -s -X POST http://localhost:9095/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"..."}' | jq -r .token)

# List VMs via REST API
curl -s http://localhost:9095/api/v1/vms \
  -H "Authorization: Bearer $TOKEN" | jq .

Show that everything available in the CLI is also available via REST API.

Demo 3: WebSocket Console Access

Duration: 3 minutes

"One of the features teams love is browser-based console access. No SSH keys to distribute, no VPN to configure -- just open the web UI and connect."

Step 1: Open the Web Dashboard

Navigate to http://localhost:9095 in the browser. Log in with admin credentials.

Point out: dark theme, clean layout, command palette (Ctrl+K).

Step 2: Navigate to the VM

Click on demo-web in the VM list. Show the VM details page with status, metrics, and action buttons.

Step 3: Open the Console

Click the "Console" button. An xterm.js terminal opens in the browser with a direct connection to the VM via authenticated WebSocket.

Step 4: Run commands in the VM

# Inside the VM console
hostname
uname -a
systemctl status

Show that you have full terminal access to the VM directly from the browser.

"The console connection is authenticated with the same JWT token as the API. No separate credentials needed. Access is controlled by RBAC -- viewers cannot open consoles."

Demo 4: Snapshot and Restore

Duration: 5 minutes

"Let me demonstrate the snapshot and backup system. This is critical for production -- you need to be able to recover from mistakes quickly."

Step 1: Create a snapshot

zyvorctl snapshot create demo-web --name=before-update

Explain: snapshots capture the full VM state at a point in time.

Step 2: Make a change in the VM

# Simulate a change (via console or SSH)
# e.g., install a package, modify a config file

Step 3: Restore the snapshot

zyvorctl snapshot restore demo-web --name=before-update

Show that the VM is back to its previous state.

Step 4: Show backup automation

# Show backup configuration
./zyvorctl backup status

# Trigger an immediate backup
./zyvorctl backup now

Explain: automated daily backups run via systemd timer with configurable retention.

"Backups run automatically at 2 AM daily with configurable retention. You can also trigger per-VM backups from the CLI, TUI, or web UI -- individually or in bulk."

Demo 5: Network Configuration

Duration: 5 minutes

"Zyvor Fabric includes 8 dedicated networking crates. Let me show you network policies and firewall rules -- this is something no other lightweight VM platform offers."

Step 1: Show current network configuration

zyvorctl network list

Step 2: Apply a firewall rule

# Allow HTTP/HTTPS, deny everything else
zyvorctl firewall demo-web --allow tcp:80,443 --deny all

Explain: per-VM firewall profiles using nftables under the hood.

Step 3: Show network policies

zyvorctl policy list

Explain: Cilium-style label-based policies control which VMs can communicate.

Step 4: Show monitoring

# Per-VM bandwidth tracking
zyvorctl net-monitor demo-web

Show real-time bandwidth usage and threshold alerts.

"Network policies, firewall rules, VPN mesh, service mesh, traffic shaping, DNS management, and NAT -- all managed through the same unified API and CLI."

Demo 6: Monitoring Dashboard

Duration: 3 minutes

"Let me switch to the web dashboard and show you the monitoring and analytics capabilities."

Step 1: Web UI Dashboard

Navigate to the main dashboard page. Point out:

  • VM count and status summary
  • Host resource utilization (CPU, memory, storage)
  • Recent activity and events
  • Real-time updates via WebSocket

Step 2: VM List with Bulk Actions

Show the VM list page. Demonstrate:

  • Select multiple VMs with checkboxes
  • Bulk start, stop, backup, delete
  • Per-VM quick actions (start, stop, console, details)

Step 3: Terminal UI (Bonus)

Navigate between views. Show sparkline graphs. Demonstrate vim keybindings. Press s to start a VM, b to backup.

Show the Prometheus-compatible metrics endpoint.

Demo 7: Clean Up

Duration: 2 minutes

"Finally, let me clean up the demo environment. This also demonstrates how easy it is to manage VM lifecycle."

Step 1: Stop the demo VMs

zyvorctl stop demo-web
zyvorctl stop demo-app

Step 2: Delete the demo VMs

zyvorctl delete demo-web
zyvorctl delete demo-app

Step 3: Verify clean state

zyvorctl list

Confirm all demo VMs are removed.

"What you have just seen is a complete VM lifecycle -- from creating VMs from cloud images, to console access, snapshots, networking, monitoring, and cleanup. All from one platform, one binary, one API."

Cloud-Init Integration

Automated VM provisioning with NoCloud datasource

What cloud-init Provides

  • Automatic hostname configuration
  • SSH key injection for passwordless access
  • User and group creation
  • Package installation on first boot
  • Custom script execution
  • Network configuration
  • Disk partition and filesystem setup

How It Works

  1. User provides cloud-init config via API or CLI
  2. vmspawnd generates a NoCloud datasource ISO
  3. ISO is attached to the VM automatically
  4. VM boots and cloud-init runs on first start
  5. Configuration is applied, VM is ready to use

Example Configuration

#cloud-config
hostname: webserver-01
users:
  - name: admin
    ssh_authorized_keys:
      - ssh-rsa AAAA...
    sudo: ALL=(ALL) NOPASSWD:ALL
packages:
  - nginx
  - docker.io
  - htop
runcmd:
  - systemctl enable --now nginx
  - systemctl enable --now docker

Snapshot and Backup System

Protect your workloads with automated retention policies

Snapshot Capabilities

  • Create point-in-time snapshots
  • Restore to any previous snapshot
  • Configurable retention policies
  • Linked clones from snapshots (CoW)
  • Snapshot before risky operations

Backup Features

  • Per-VM backup from any interface (CLI, TUI, Web)
  • Bulk backup operations
  • Incremental backup support
  • Automated daily backups via systemd timer
  • Configurable backup schedule (default 2:00 AM)
  • Retention policies with automatic cleanup

Backup Configuration

# In vmspawnd.toml
[backup]
dir = "/var/lib/vmspawnd/backups"
retain = 7
type = "full"

# Or via environment variables
VMSPAWND_BACKUP_DIR=/backups
VMSPAWND_BACKUP_RETAIN=7
VMSPAWND_BACKUP_TYPE=full

Management Commands

# Immediate backup
vmspawnctl backup now

# Enable daily timer
vmspawnctl backup enable

# Check backup status
vmspawnctl backup status

# View backup logs
vmspawnctl backup logs

Live Migration

Move running VMs between hosts with minimal downtime

How It Works

  1. Pre-copy phase -- iterative rsync of VM disk to target host
  2. Memory transfer -- copy VM memory pages
  3. Convergence -- track dirty pages, re-copy changed regions
  4. Cutover -- brief pause, final sync, resume on target
  5. Cleanup -- remove source VM data

Storage Live Migration

  • Move VM disks between storage pools
  • Migrate from local to shared storage
  • No VM downtime during disk migration
  • Supports all 6 storage backends

Migration Triggers

  • Manual -- operator-initiated via CLI, API, or Web UI
  • DRS -- automatic load balancing across cluster
  • Maintenance -- evacuate host for planned downtime
  • Failover -- automatic migration on host failure

Placement Controls

  • Affinity rules -- keep VMs together
  • Anti-affinity rules -- separate VMs across hosts
  • Host constraints -- restrict VMs to specific nodes
  • Resource requirements -- CPU, memory, GPU matching

Advanced Networking

8 dedicated networking crates for enterprise requirements

Network Policies

Cilium-style label-based rules for ingress and egress traffic control. Define which VMs can communicate using label selectors.

allow:
  from:
    label: tier=web
  to:
    label: tier=api
  port: 8080

VM Firewall

Per-VM firewall profiles using nftables. Stateful packet inspection with connection tracking. Security zones for network segmentation.

vmctl firewall myvm \
  --allow tcp:80,443 \
  --deny all

VPN Mesh

WireGuard-based encrypted tunnels. Supports point-to-point, hub-spoke, and full-mesh topologies for secure cross-network VM communication.

vmctl vpn create \
  --topology full-mesh \
  --peers vm1,vm2,vm3

Service Mesh

Virtual IP load balancing across VM groups. Algorithms: round-robin, least-connections, random, IP-hash. Health checks included.

Traffic Shaping (QoS)

Per-VM bandwidth guarantees and limits. Burst capacity configuration. Priority-based allocation for critical workloads.

DNS, NAT, Monitoring

DNS zone management with domain blocking. Full NAT (masquerade, SNAT, DNAT, hairpin). Per-VM bandwidth tracking with alerts.

RBAC Model

Admin

Full platform access. Manage users, projects, quotas, cluster settings. Access all VMs across all projects.

User

Create and manage VMs within assigned projects. Configure networking and storage. Cannot modify platform settings.

Viewer

Read-only access to assigned projects. View VM status, metrics, and logs. Cannot modify any resources.

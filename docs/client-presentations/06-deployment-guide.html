Deployment Architecture Options

Single Server

One Linux server running Zyvor Fabric with local storage.

Best for:

  • Development and testing
  • Small teams (1-10 users)
  • Edge / branch office
  • Home lab

Requirements:

  • 1 Linux server
  • Local or NFS storage

Multi-Node Cluster

Multiple Zyvor Fabric nodes with shared storage and HA.

Best for:

  • Production workloads
  • Teams needing HA
  • Live migration
  • Mid-size deployments

Requirements:

  • 3+ Linux servers
  • Shared storage (NFS/Ceph)
  • etcd cluster

Kubernetes-Managed

Zyvor Fabric nodes managed via Kubernetes operator.

Best for:

  • Mixed container + VM workloads
  • GitOps workflows
  • Large-scale deployments
  • Platform teams

Requirements:

  • Kubernetes cluster
  • Zyvor Fabric operator deployed
  • Bare-metal or nested-virt nodes

Configuration Overview

One config file, sensible defaults, environment variable overrides

Config File: /etc/zyvor-fabricd/zyvor-fabricd.toml

# Core settings
[server]
listen = "0.0.0.0:9095"
workers = 4

# Authentication
[auth]
jwt_expiry = "24h"
session_timeout = "8h"

# Storage
[storage]
default_pool = "local"
image_dir = "/var/lib/zyvor-fabricd/images"

# Backup
[backup]
dir = "/var/lib/zyvor-fabricd/backups"
retain = 7
type = "full"

# TLS (optional)
[tls]
cert = "/etc/zyvor-fabricd/tls/cert.pem"
key = "/etc/zyvor-fabricd/tls/key.pem"

Environment Variable Overrides

VariablePurpose
ZYVOR_FABRICD_LISTENServer bind address
ZYVOR_FABRICD_BACKUP_DIRBackup directory
ZYVOR_FABRICD_BACKUP_RETAINBackup retention (days)
ZYVOR_FABRICD_BACKUP_TYPEBackup type (full/incremental)

Auto-Generated Files

  • /etc/zyvor-fabricd/jwt-secret -- JWT signing key (0600)
  • /etc/zyvor-fabricd/admin-password -- Initial admin password (0600)
  • /var/lib/zyvor-fabricd/ -- Data directory

File Permissions

  • Secret files: 0600 (owner read/write only)
  • Config files: 0644
  • Data directory: 0755

Day 1: Deploy and Verify

From bare server to running VM platform

Step 1: Deploy

# One-command deployment (handles deps, build, install, start)
./zyvorctl deploy

Step 2: Verify

# Post-install smoke test (API, auth, VM CRUD, backups)
./zyvorctl verify

# Deep health check (disk, DB, timers, resources, KVM)
./zyvorctl health

Step 3: Get Admin Credentials

# Read auto-generated admin password
./zyvorctl password

Step 4: Enable TLS (Recommended)

# Generate self-signed certificate
./zyvorctl tls

# Restart with TLS enabled
./zyvorctl restart

Step 5: Create Your First VM

zyvorctl create test-vm --image=/path/to/ubuntu-24.04.qcow2 --cpus=2 --memory=2048
zyvorctl start test-vm
zyvorctl list

Day 2: Ongoing Operations

Operational tasks for production environments

Routine Operations

Service Management

./zyvorctl status    # Check service
./zyvorctl logs      # Follow logs
./zyvorctl restart   # Restart daemon

Backup Management

./zyvorctl backup enable   # Daily 2 AM
./zyvorctl backup status   # Check timer
./zyvorctl backup now      # Manual backup

Upgrades

# Pull latest + rebuild + reinstall + verify
./zyvorctl upgrade

Monitoring

Health Checks

./zyvorctl health    # Full system check
./zyvorctl doctor    # Readiness check

Prometheus Integration

# Add to prometheus.yml
scrape_configs:
  - job_name: Zyvor Fabric
    static_configs:
      - targets: ['host:9095']
    metrics_path: /metrics

Alert Configuration

  • Configure email, Slack, Teams, or webhook alerts
  • Set thresholds for CPU, memory, disk, network
  • Webhook notifications include retry with backoff

Scaling Considerations

Growing from single server to multi-node cluster

Vertical Scaling (Single Server)

ScaleVMsServer Spec
Small1-104 cores, 16 GB, 500 GB SSD
Medium10-5016 cores, 64 GB, 2 TB NVMe
Large50-10032 cores, 128 GB, 4 TB NVMe

Zyvor Fabric Overhead

  • Daemon: ~20 MB RSS
  • Per-VM tracking: minimal (~1 KB state)
  • API latency: sub-millisecond
  • CPU overhead: negligible

Horizontal Scaling (Cluster)

  • Add nodes: Install Zyvor Fabric, join etcd cluster
  • Shared storage: NFS for simple, Ceph for HA
  • Load distribution: DRS auto-balances VMs
  • Live migration: Move VMs without downtime

Storage Scaling

  • Local: Add disks, extend volume groups
  • NFS: Scale NFS server or add mounts
  • ZFS: Add vdevs to pools
  • Ceph: Add OSDs for capacity and throughput

Network Scaling

  • VLANs for network segmentation
  • Bond NICs for bandwidth
  • WireGuard mesh for cross-site
